# PostgreSQL

Реализации интерфейсов `usecase/post.Repository` и `usecase/comment.Repository`
используют общий `pgxpool.Pool`. Зависимости: pgx v5 и Goose v3; версии закреплены в `go.mod`.

## Структура

- `config.go`, `pool.go` — настройки, создание и проверка пула, подготовка SQL.
- `migrate.go`, `migrations/*.sql` — встроенные версионированные миграции Goose.
- `transaction.go`, `errors.go` — транзакции и преобразование ошибок.
- `parameters.go`, `rows.go` — параметры пакетных запросов и чтение доменных объектов.
- `queries/*.sql`, `queries/statements.go` — SQL и имена prepared statements.
- `post/` — создание, чтение, страницы постов и изменение разрешения на комментарии.
- `comment/` — создание, чтение по ID и пакетные страницы корней/ответов.

Тесты лежат рядом с реализациями. `testdb` создаёт отдельную временную
схему для каждого интеграционного теста и удаляет только её после проверки.

## Локальный запуск БД и миграций

Из корня проекта в PowerShell:

```powershell
docker compose up -d --wait postgres
$env:DATABASE_URL='postgres://ozon:ozon_dev@localhost:5432/ozon_bank?sslmode=disable'
go run ./cmd/migrate
```

Compose сохраняет данные в volume `postgres_data`. Пароль для локальной разработки
по умолчанию — `ozon_dev`; переменная `POSTGRES_PASSWORD` переопределяет его при
первой инициализации БД. Значение в `DATABASE_URL` должно совпадать с этим паролем.

`Migrate` выполняет версии внутри транзакций и использует PostgreSQL advisory lock,
чтобы несколько экземпляров мигратора не применяли одну версию одновременно.
Повторный запуск безопасен. Миграции используют отдельное соединение через
pgx/stdlib: таблиц может ещё не быть, а основной пул сразу подготавливает запросы к ним.
Команда ограничена двумя минутами и возвращает ненулевой код при ошибке.

## Подключение к usecase

Ниже фрагмент сборки зависимостей для функции, принимающей `ctx context.Context`
и возвращающей `error`. Импорты репозиториев используют алиасы:

```
import (
    "OzonBankTestTask/internal/repositories/postgres"
    commentrepo "OzonBankTestTask/internal/repositories/postgres/comment"
    postrepo "OzonBankTestTask/internal/repositories/postgres/post"
)
```

```
config := postgres.Config{DSN: os.Getenv("DATABASE_URL"), MaxConns: 16, MinConns: 2}
if err := postgres.Migrate(ctx, config); err != nil {
    return err
}
pool, err := postgres.Open(ctx, config)
if err != nil {
    return err
}
defer pool.Close()

postRepository := postrepo.New(pool)
commentRepository := commentrepo.New(pool)
posts := postusecase.New(postRepository)
comments := commentusecase.New(commentRepository, hub)
subscriptions := subscription.New(posts, hub)
```

Создание `hub` и HTTP/GraphQL-обработчика описано в
[README API](../../api/README.md). Один пул обслуживает оба репозитория весь срок
работы сервиса. Закрывать его нужно после остановки обработчиков и завершения
текущих запросов. `cmd/service` пока не содержит сборку приложения;
`cmd/migrate` — отдельная исполняемая команда для подготовки БД.

Миграции можно выполнить отдельным шагом перед запуском приложения. В этом случае
в приложении достаточно вызвать `Open`. Без применённых миграций он вернёт ошибку
подготовки запросов, а не готовый к работе пул.

## Пул и prepared statements

Нулевые поля `Config`, кроме обязательного `DSN`, задают следующие значения:

- `MaxConns`: 16; `MinConns`: 0.
- `ConnectTimeout`: 5 секунд; также ограничивает начальную проверку `Open`.
- `MaxConnLifetime`: 30 минут, случайный разброс до 10%.
- `MaxConnIdleTime`: 5 минут; `HealthCheckPeriod`: 30 секунд.

Отрицательные значения и `MinConns > MaxConns` отвергаются. Поля `Config`
определяют эти настройки, включая значения по умолчанию, даже если в DSN есть
одноимённые параметры пула. DSN задаёт адрес, учётные данные, TLS и параметры
сессии; часовой пояс сессии устанавливается в UTC. `pool.Stat()` доступен для метрик.
Ожидание свободного соединения и запросы ограничиваются контекстом вызывающего кода.

`AfterConnect` вызывает `Conn.Prepare` для всех именованных запросов из
`queries.All()` на **каждом физическом соединении**, в том числе после его замены.
Репозитории выполняют запросы по этим именам; значения передаются отдельно через
`$1`, `$2` и массивы параметров. Пользовательские значения не подставляются в SQL.
`Open` проверяет соединение через `Ping` и закрывает пул при ошибке инициализации.
Поведение хуков и подготовленных запросов описано в документации
[pgxpool](https://pkg.go.dev/github.com/jackc/pgx/v5/pgxpool) и
[pgx.Conn.Prepare](https://pkg.go.dev/github.com/jackc/pgx/v5#Conn.Prepare).

Настройка рассчитана на прямое соединение с PostgreSQL либо session pooling.
При добавлении PgBouncer в transaction pooling нужно отдельно согласовать
поддержку именованных prepared statements с его версией и конфигурацией.

## Атомарность и чтение

`CreateComment` в транзакции `READ COMMITTED` читает пост с `FOR SHARE`, проверяет
разрешение комментирования и родителя, затем вставляет комментарий. Параллельные
вставки совместимы. `SetCommentsEnabled` держит конфликтующий `FOR UPDATE` и
проверяет автора: отключение ждёт уже начатые защищённые вставки, а новая вставка
после отключения получает `ErrCommentsDisabled`.

Результат записи возвращается только после успешного `COMMIT`, поэтому существующий
usecase публикует событие подписки после фиксации. Ошибка/отмена вызывает rollback
с отдельным контекстом очистки. Записи автоматически не повторяются: при сетевом
сбое результат COMMIT может быть неизвестен. Гарантии доставки событий остаются
такими, как описано в README API.

FK проверяют существование поста и принадлежность родителя тому же посту, CHECK —
запрет ссылки на себя и длину текста в 1–2000 символов PostgreSQL `char_length`.
Доменная валидация выполняется до SQL и при чтении сохранённых объектов.
Ошибки БД получают `domain.ErrStorage`, сохраняя исходную ошибку для `errors.As`;
бизнес-ошибки и отмена контекста сохраняют свою классификацию.

Списки используют keyset-пагинацию `(created_at DESC, id DESC)` и `LIMIT first+1`.
Время хранится как `timestamptz(6)` и возвращается в UTC. Индексы соответствуют
сортировке; корни и ответы используют отдельные частичные индексы. Пакетные страницы
передают до 100 запросов массивами в один SQL с `unnest WITH ORDINALITY` и `LATERAL`:
сохраняются порядок, повторяющиеся владельцы и разные курсоры. Ограничение выборки
действует для каждой страницы. Отдельные ветки для наличия/отсутствия курсора
не заставляют фильтровать всю предыдущую часть обсуждения условием `OR`.
Отсутствующий владелец страницы возвращает доменную ошибку, существующий без
комментариев — пустую страницу. Поиск по ID пропускает отсутствующие записи.

## Проверки

```powershell
# Без TEST_DATABASE_URL интеграционные тесты явно пропускаются.
go test ./...
go vet ./...

# Использовать отдельную тестовую БД; нужны права CREATE SCHEMA.
$env:TEST_DATABASE_URL='postgres://postgres:postgres@localhost:5432/ozon_test?sslmode=disable'
go test ./internal/repositories/postgres/... -count=1 -timeout=3m
```

Интеграционные проверки используют реальный PostgreSQL: prepared statements на
каждом и заменённом соединении, лимит пула, миграции, Unicode и FK, совпадающие времена
в курсорах, порядок пакетных страниц, число SQL-выполнений, конкурентные блокировки,
отмену ожидания и отказ COMMIT без события. CI поднимает PostgreSQL 17 и запускает
эти проверки вместе с остальными тестами и race detector.
