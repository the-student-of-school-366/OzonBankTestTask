# PostgreSQL

Реализации `usecase/post.Repository` и `usecase/comment.Repository` используют общий `pgxpool.Pool`. В сервисе пул создаёт сборка `cmd/service`. Зависимости пакета — pgx v5 и Goose v3, версии закреплены в `go.mod`.

## Состав пакета

- `config.go`, `pool.go` — настройки, создание и проверка пула, подготовка SQL.
- `migrate.go`, `migrations/*.sql` — встроенные миграции Goose.
- `transaction.go`, `errors.go` — транзакции и преобразование ошибок.
- `parameters.go`, `rows.go` — параметры пакетных запросов и чтение доменных объектов.
- `queries/*.sql`, `queries/statements.go` — текст запросов и имена prepared statements.
- `post/` — создание, чтение, страницы постов и разрешение на комментарии.
- `comment/` — создание, чтение по идентификатору и пакетные страницы корней и ответов.

Тесты лежат рядом с кодом. `testdb` создаёт отдельную схему на каждый интеграционный тест и удаляет только её.

## Миграции

Из корня проекта:

```powershell
docker compose up -d --wait postgres
$env:DATABASE_URL = 'postgres://ozon:ozon_dev@localhost:55432/ozon_bank?sslmode=disable'
go run ./cmd/migrate
```

Compose хранит данные в томе `postgres_data`. Пароль локальной базы по умолчанию — `ozon_dev`. `POSTGRES_PASSWORD` меняет его при первой инициализации тома. Пароль в `DATABASE_URL` должен совпадать с паролем базы.

`Migrate` применяет версии в транзакциях и держит advisory lock, чтобы несколько экземпляров не накатывали одну версию одновременно. Повторный запуск безопасен. Для миграций используется отдельное соединение: таблиц ещё может не быть, а основной пул сразу готовит запросы к ним. Команда ограничена двумя минутами и при ошибке завершается ненулевым кодом.

Миграции можно выполнить до старта приложения. Тогда приложению достаточно `Open`. Без миграций `Open` завершается ошибкой подготовки запросов.

## Пул и prepared statements

Нулевые поля `Config`, кроме обязательного `DSN`, получают такие значения:

- `MaxConns`: 16, `MinConns`: 0.
- `ConnectTimeout`: 5 секунд. Этот же предел действует на первую проверку `Open`.
- `MaxConnLifetime`: 30 минут, случайный разброс до 10%.
- `MaxConnIdleTime`: 5 минут, `HealthCheckPeriod`: 30 секунд.

Отрицательные значения и `MinConns > MaxConns` отвергаются. Поля `Config` задают параметры пула и тогда, когда в DSN есть одноимённые параметры. DSN задаёт адрес, учётные данные, TLS и параметры сессии. Часовой пояс сессии — UTC. Ожидание свободного соединения и сами запросы ограничены контекстом вызывающего кода.

`AfterConnect` вызывает `Conn.Prepare` для всех запросов из `queries.All()` на каждом физическом соединении, в том числе после его замены. Репозитории выполняют запросы по этим именам. Значения передаются отдельно через `$1`, `$2` и массивы. Данные клиента в текст SQL не подставляются. `Open` проверяет соединение через `Ping` и при ошибке закрывает пул.

Настройка рассчитана на прямое соединение или session pooling. Для PgBouncer в режиме transaction pooling нужно отдельно проверить поддержку именованных prepared statements.

## Запись и чтение

`CreateComment` в транзакции `Read Committed` читает пост с `FOR SHARE`, проверяет разрешение и родителя, затем вставляет комментарий. Параллельные вставки совместимы. `SetCommentsEnabled` держит `FOR UPDATE` и проверяет автора. Отключение ждёт уже начатые вставки, а вставка после отключения получает `ErrCommentsDisabled`.

Результат записи возвращается после успешного `COMMIT`. Usecase публикует событие подписки после этого. Ошибка или отмена вызывает rollback с отдельным контекстом очистки. Запись автоматически не повторяется: при сетевом сбое исход `COMMIT` может быть неизвестен.

Внешние ключи проверяют существование поста и принадлежность родителя тому же посту. `CHECK` запрещает ссылку на себя и ограничивает текст 1–2000 символами `char_length`. Доменная проверка выполняется до SQL и при чтении сохранённых объектов. Ошибки базы получают `domain.ErrStorage` и сохраняют исходную ошибку для `errors.As`. Бизнес-ошибки и отмена контекста остаются в своих типах.

Списки используют keyset-пагинацию `(created_at DESC, id DESC)` и `LIMIT first + 1`. Время хранится как `timestamptz(6)` и возвращается в UTC. Индексы совпадают с сортировкой. Корни и ответы лежат в отдельных частичных индексах. Пакетные страницы передают до 100 запросов массивами в один SQL: `unnest WITH ORDINALITY` и `LATERAL`. Сохраняются порядок, повторы владельцев и разные курсоры. Ограничение действует на каждую страницу. Ветки с курсором и без него разделены, поэтому предыдущая часть обсуждения не отфильтровывается одним условием `OR`. Отсутствующий владелец страницы даёт доменную ошибку. Существующий владелец без комментариев даёт пустую страницу. Поиск по идентификатору пропускает отсутствующие записи.

## Проверки

```powershell
go test ./internal/repositories/postgres/... -count=1
```

Без `TEST_DATABASE_URL` интеграционные тесты пропускаются. Для них нужна отдельная база с правом `CREATE SCHEMA`:

```powershell
$env:TEST_DATABASE_URL = 'postgres://postgres:postgres@localhost:5432/ozon_test?sslmode=disable'
go test ./internal/repositories/postgres/... -count=1 -timeout=3m
```

Проверяются prepared statements на новом и заменённом соединении, лимит пула, миграции, Unicode и внешние ключи, совпадающее время в курсорах, порядок пакетных страниц, число выполнений SQL, конкурентные блокировки, отмена ожидания и отказ `COMMIT` без события. CI поднимает PostgreSQL 17 и запускает эти тесты вместе с остальными и с race detector.
