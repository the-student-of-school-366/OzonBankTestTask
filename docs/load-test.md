# Нагрузка GraphQL

Прогон 13 ноября 2026 года на локальной машине. Сервис отвечал без ошибок. Запись комментария остаётся дешёвой. Тяжёлое чтение списка постов вместе с комментариями и ответами выходит на предел около 330 запросов в секунду.

## Стенд

- Процессор: Intel Core i5-13500H, 12 ядер, 16 потоков.
- Приложение: `go run ./cmd/service` на Windows, PostgreSQL, `SANDBOX_ENABLED=false`, адрес `127.0.0.1:18081`.
- База: PostgreSQL 17 в Docker, отдельная база `ozon_load`. После прогона база удалена.
- Пул соединений — значения по умолчанию, до 16 соединений.
- Клиент: `go run ./cmd/loadtest`. Каждый запрос шёл с заголовком `X-User-ID: load`.

Это не образ из Compose и не длительный прогон. Цифры показывают порядок величины на этой машине.

## Данные и запросы

Перед измерениями создано 40 постов. У каждого 25 корневых комментариев. У первых пяти корней каждого поста по 4 ответа. На старте в базе 1800 комментариев.

Чтение запрашивает 20 постов, у каждого 10 корней и у корня до 5 ответов:

```graphql
query($first: Int!) {
  posts(first: $first) {
    nodes {
      id
      title
      comments(first: 10) {
        nodes {
          id
          text
          replies(first: 5) { nodes { id text } }
        }
      }
    }
  }
}
```

Запись создаёт один корневой комментарий к случайному из этих постов. В смешанной фазе каждый четвёртый запрос — запись, остальные — то же чтение.

Запросы с отменой по концу фазы в статистику не входят. Ошибкой считается HTTP-статус не 200 или поле `errors` в ответе GraphQL.

## Что из этого следует

Один клиент читает такую страницу за 16 мс в медиане. Восемь клиентов поднимают поток до 281 запроса в секунду, медиана вырастает до 28 мс. Тридцать два клиента дают только 333 запроса в секунду, а медиана становится 89 мс. Дальше добавлять клиентов почти бесполезно: сервис на этом запросе уже занят. Пул из 16 соединений здесь правдоподобный предел, но прогон его отдельно не менял.

Запись одного комментария при восьми клиентах идёт со скоростью около 1500 запросов в секунду, медиана 5 мс. Вставка короче, чем сборка вложенных страниц.

Смешанная нагрузка остаётся между этими режимами: 679 запросов в секунду и медиана 25 мс. Ошибок нет, ответы GraphQL успешные.

Запрос чтения как раз тот, где без пакетной загрузки база получила бы отдельный запрос на каждый пост и каждый комментарий. Здесь страница строится пакетно, и при одном клиенте уложилась в десятки миллисекунд на 20 постов с двумя уровнями комментариев.

## Чего прогон не показывает

Подписки, страница `web` и образ distroless не участвовали. Длительность фаз — 8–10 секунд, это не поиск утечек и не суточный запас. Повторяемость на другой машине будет другой. Чтобы повторить прогон, поднимите сервис с PostgreSQL и выполните `go run ./cmd/loadtest -url http://127.0.0.1:18081/graphql`.
